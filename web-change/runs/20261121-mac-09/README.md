# 跨项目真实对比度改动与版本匹配捕获

本轮已实际重放**2个新增项目、3次真实提交**，完成12次新Chrome进程捕获。3次提交的前后控件区域均同尺寸、同语义状态和字体声明，并有可见像素变化；6组同版本独立重复捕获均为零像素差。

但来源隔离门槛未满足：两个项目都继承`cbracco/html5-test-page`，目标控件区域规范化HTML指纹完全相同，保守只算**1个独立fixture族**。因此本轮停在数据证据，**没有运行像素／边缘检测器比较、JPEG误报评分、阈值选择或训练**。

## 匹配的无改动对照

每个源版本分别启动两个全新浏览器进程和上下文，重新加载该版本的HTML/CSS，得到一组重复对照，共6组。没有复用PNG，也没有将“同一个仓库图片文件”当作独立捕获。

固定条件为同一已安装Chrome版本、1280×1000 viewport、deviceScale1、light、en-US、Asia/Shanghai、同机系统字体。每张图记录控件文本、值、disabled/checked状态、字体声明／字号、控件几何、主题、焦点、所需CSS响应指纹及截图哈希。前后和重复捕获的语义／字体／几何签名均匹配。Sakura仅通过原页面的主题切换按钮选取相同earthly状态，没有由我们写入CSS或DOM节点。

捕获的是原测试页的控件区域，而非整页：原页其他演示区中的外部图片、媒体和iframe被阻断，逐项记录为目标外依赖；目标区域本身不含这些媒体。若缺失可能影响目标的CSS、脚本、字体、fetch/XHR，或缺失声明的源资源，则不能通过重复捕获契约。Simple每次所需HTML/CSS响应2项，Sakura每次4项，全部与已验证源文件哈希一致；本轮没有相关依赖错误。两项目的许可证均为MIT，原始许可保留本地。

六组零像素差只说明这些固定源版本、状态和本机环境的控件区域捕获稳定；不代表跨操作系统、浏览器、线上动态页或总体误报率为零。源代码和像素校验中的“>4”沿用既有审计统计，只用于核验输入，不是选出的检测阈值。

## 为什么不做检测比较

两份原HTML都明确署名上游`cbracco/html5-test-page`。三个case目标区域的规范化HTML SHA256均为`2320ae1f792ebde7ed2e31a5c45630f719d36b21143695abd53227fa3c169122`。只按仓库名拆分会掩盖共同测试内容，因此合并来源族；本轮不能把两个仓库写成独立页面家族的泛化验证。

`protocol.json`在捕获前规定：需要至少3个独立项目／fixture组、候选标签复核、版本匹配的重复对照，以及预先冻结的来源隔离分配，才进入便宜检测比较。当前只有1个保守组。`outputs/comparison_gate.json`记录门槛失败，未运行像素／边缘检测误报或漏检评分，也未运行JPEG检测。已揭盲419对及历史确认数据均未用于选择或调参。

## 证据、边界与继续条件

`outputs/source_files.json`、`source_specs.json`保存22条源文件引用及13个唯一blob依据；`outputs/captures.json`记录12次独立启动和控件状态；`outputs/repeat_pixels.json`、`outputs/version_pixels.json`保留原尺寸像素审计；`outputs/style_evidence.json`和`outputs/candidate_labels.json`说明各候选子类；`outputs/fixture_lineage.json`记录共同谱系证据。独立复核确认上述配对／捕获与标签限制，3项契约测试先红后绿通过。

当前新增了可追溯的真实对比度变化和真正匹配源版本的重复对照，但未解决独立来源和人工标签不足。继续条件是取得不共享该测试模板的真实页面／控件修复，补足多个独立项目／fixture族，进行独立标签／区域复核，并在来源隔离分配冻结后才比较像素、边缘及JPEG鲁棒性。边界颜色与文字／填色恢复需分开定义，不能混为一个已证实类别。
