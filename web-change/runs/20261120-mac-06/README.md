# 一次开发收尾检查：JPEG与缺类生成

本轮按预先固定的协议，只使用四个训练家族和两个开发家族。旧419对确认样本、其他六个确认家族及历史确认数据均未参与评分、阈值选择或候选比较。只测试一个固定预处理候选，结果不满足预设增益条件，至此停止本机调参。

## JPEG检查

从Spectre/Chota各现有类别确定性选一对（优先强度level1），共19对变更；负例使用10个训练基准视图校准标量阈值、6个开发基准视图读数。视图只来自两个开发家族，不能视为六个独立网站。

唯一候选是：对收到的前后两帧各JPEG90重编码一次；若后帧已压缩，它会再次编码。学习方法复用run05模型与阈值0.953333；不重训、不挑阈值。局部最大残差则在各管线独立用训练负例校准，因此其比较包含预处理和阈值两项变化，不能单独归因为编码噪声。

|冻结学习方法|干净变更检出|JPEG95变更检出|一像素偏移变更检出|最差开发误报|
|---|---:|---:|---:|---:|
|原始输入|16/19|13/19|16/19|1/6（JPEG98）|
|两帧各JPEG90一次|19/19|14/19|13/19|1/6（JPEG98）|

误报总数未下降，偏移变更检出还下降；未通过预设开发增益条件。误报并非同一视图：原始输入为`chota_v640`，分数0.973333；候选为`chota_v320`，分数0.96。两者均超过同一个冻结阈值。局部最大残差两管线都为13/19检出、各条件0/6误报，不能提供误报下降的证据；其阈值分别0.061351和0.050961。小样本0/6不构成总体零误报保证。

在固定渲染环境中，六个开发视图重新渲染均与run05基准像素相同；identity和一像素偏移无改动对照均未误报。构造单边JPEG负例会触发上述误报；相同帧两侧使用同一JPEG编码时，像素差和误报为0。这最后一项是构造一致性检查，不能证明真实网页误报由JPEG主导，也不是对单边已压缩输入的部署修复。此轮未采集真实浏览器差异或未知压缩链路异常。

## justify/position生成验证

仅在两个开发家族、每家族三个既定视图上验证像素可见性，不运行模型，也不把新图加入已冻结的run05。

- position优先选择已有非inline、有填色或边框的盒子，执行1/2/4像素平移；该可见性筛选是近似规则，最终仍需像素和人工审查。Spectre尝试27次，得到6张新像素结果（同一个v640视图中的两个按钮，各三档强度）；其余21次未改变像素。六张结果已人工查看，按钮边界与内容一起平移，且未碰撞旧开发样本的像素哈希。Chota没有满足条件的目标。
- justify要求已有横向nowrap flex容器、至少两个可见子元素且剩余宽度不少于8像素。两个家族的六个视图均无合格目标，未通过人为添加布局或改内容补造。

因此只能证明position在部分已有布局中可生成，**缺类问题尚未解决**。需要具有真实可用flex剩余空间的页面，以及多个独立训练来源中的可平移盒子；还需同时保证所有目标类别在训练与新确认来源中有足够支持。仅向当前数据补六张图不能解决站点隔离或统计覆盖。

## 证据与结论

`outputs/summary.json`、`outputs/decisions.csv`保存完整开发结果；`outputs/generation_summary.json`和`outputs/generation_decisions.json`保存生成尝试及失败原因。代码/配置/依赖输入分别由`design_lock.json`和`generation_lock.json`固定。3项JPEG选择/变换测试和2项目标生成测试均先红后绿，结果独立重算核验；原始图像、特征、模型和日志仅保留本地。运行约43.9秒CPU，无付费API、无租赁算力，Word任务书未修改。

当前方法的本机证据边界已到达：没有可信的压缩误报改善，justify仍需新的适用来源布局。后续有意义的验证依赖类别覆盖充分、具有真实站点标识且未揭盲的新数据；本轮不继续循环调参，不宣称真实站点泛化。
