# 真实改动窄类候选与独立重复捕获

本轮取得实际新证据：保留**控件配色／对比度恢复（contrast_recovery）**这一窄类的6个真实截图实例；完成8次独立浏览器进程捕获，形成4组同一固定资源产物的重复对照，四组像素差均为0。其中3组资源检查完整，另1组存在图标fetch检查缺口，仅部分核验。未训练、未调参、未租卡，未使用已揭盲419对确认样本，Word任务书保持冻结。

这仍是候选小样本：6张正例来自**同一个项目、同一次真实提交**，不是6次独立改动；尚未建立多项目稳定收集能力，也不是独立人工标注的13类金标。

## 可保留的窄类候选

来源：[Ionic实际按钮修复 ee5da7a，2024-04-02](https://github.com/ionic-team/ionic-framework/commit/ee5da7a747c0a0b420c5e371a9fe9ec4938d179e)。取该提交与第一父提交中同路径的全部6张modified PNG，覆盖Chrome/Firefox/Safari以及LTR/RTL。逐文件核验Git blob；每一对尺寸一致（224×393或224×390），没有缩放或手工CSS注入。

源码调整激活态outline按钮的前景、背景与暗色主题变量。6实例均可见同一现象：STAR按钮由低对比不可见，变为白字、白色轮廓可见；变化局限于该按钮区域。逐例非零变化为848–884像素，通道最大差值>4的变化为823–873像素。源码与像素复核支持统一保留为`contrast_recovery`候选，见`outputs/narrow_labels.json`。

这个标签表示一个配色对比度修复机制，不表示只改一个CSS属性、纯文字颜色，或已完成因果拆分。不能把它标成新增文字、图标、边框结构或位置变化，也不据此宣称符合可访问性标准。该修复为2024历史项目实例，并非近期生产网站变化。

其他候选按证据排除：

|候选|实际核验结果|处理|
|---|---|---|
|Ionic checkbox对齐修复|提交新增测试截图，无对应父版本PNG；精确历史源码构建/复现本轮未运行|未产出position／justify配对；不把“未运行”说成无法复现|
|Ionic round按钮改动|同时变更图标字号、控件尺寸、padding和截图区域|不归为纯rounded|
|MDN加入display:grid|原始下载页的两个固定版本各独立捕获两次；两次前后比较均0像素变化|排除可见布局正例|
|MDN logical-width-height|源码涉及规则顺序／编辑器文本，本轮未渲染|不假定可见单类变化|

MDN实测为0与源码一致：原有元素同时带`media media-flip`，`.media`已经指定grid；新增相同display声明在该固定页面和1280×1600环境没有产生可见变化。源码修改或提交关键词本身不等于视觉正例。

## 真正独立的重复捕获

每张计入的截图均新启动一个Chrome进程、创建新上下文并重新加载，不复用PNG或浏览器缓存。固定1280×1600、deviceScale1、en-US、Asia/Shanghai、light，等待字体、图片及Ionic组件就绪；采用浏览器截图的动画禁用选项，没有改写HTML/CSS或注入变更。

|固定产物|独立捕获|像素差|质量范围|
|---|---:|---:|---|
|MDN修改前固定源码＋图片|2次|0|全部3项资源响应指纹核对完整|
|MDN修改后固定源码＋图片|2次|0|全部3项资源响应指纹核对完整|
|Ionic checkbox当前页面归档|2次|0|全部31项归档资源响应指纹核对完整|
|Ionic toolbar当前页面归档|2次|0|固定HAR和图标目视检查成立，但6项SVG fetch未纳入响应／失败／就绪自动检查；仅部分核验|

MDN源码及图片按固定Git blob下载，在本地原样提供。Ionic两个公开测试页各只进行一次资源采集，保存完整HAR；两次计入的捕获分别由新Chrome进程离线重放同一HAR。采集过程本身不计为重复对照。完整HAR字节指纹已核验，禁止使用未记录的网络响应。

Ionic公开部署别名没有暴露精确Git提交身份，因此这些对照只能证明**当前归档产物在本机固定环境下的捕获稳定性**。它们没有重现2024正例的版本与Linux浏览器环境，不能用来估计历史正例噪声，也不能由4组零差异推导总体误报率。MDN是文档示例项目，Ionic是组件项目，都不称为独立生产站点泛化。

`outputs/control_quality.json`明确区分3组完整检查与1组部分检查；`outputs/repeat_pixel_audit.json`和`outputs/mdn_version_pixel_audit.json`保存原尺寸结果。

## 失败与修正

首轮脚本把已收集资源记录的URL字符串当成Playwright方法调用，截图生成后在资源汇总阶段报错。4张未完成记录的PNG全部排除计数；失败代码、锁、结果与日志保留在本地`attempts/capture01/`，图片在本地`failed_capture01/`。修正资源汇总逻辑并添加回归测试后，使用已保存的两份相同HAR重新捕获，没有再次采集线上页面，没有改动像素或标签标准。当前4项契约测试通过，先红后绿记录留档。

独立复核确认配对、锁、HAR及独立启动记录；同时指出并保留上述SVG检查限制。不会把修复前的失败记录抹去或并入有效对照。

## 来源、许可与复现

Ionic修复源码与图片的固定版本许可证为MIT；MDN固定源码许可证为CC0-1.0。原始许可、HTML、图片、HAR及日志只在本地保存；公开仓库仅含代码、配置、来源指针、文件指纹和筛选后的核验记录。

入口依次为`python code/acquire.py`、使用既有Playwright/Chrome运行`code/replay.mjs`、`python code/finalize.py`。原始版本由`source_specs.json`固定，运行设计见`protocol.json`、`source_lock.json`和`capture_lock.json`。公开协议移除了机器Word路径，其导出哈希与本地原始冻结哈希应分别核验。Ionic线上别名重采集将生成新产物，不能声称逐字节复现本地保存的HAR；精确复核需使用本地原始归档。浏览器与环境信息保留在捕获记录中。

## 本轮边界和继续条件

能保留的是：一类有源码和像素依据的真实改动候选，以及少量真正重新渲染的无改动对照。纯justify、position仍没有补齐。本轮没有运行JPEG检测、模型评分或阈值选择，因此旧JPEG误报问题仍未解决。

下一步应围绕这个窄类取得多个独立真实提交和项目，完成独立标签／区域复核，并补与正例历史版本、浏览器、字体和状态匹配的重复对照，包含完整fetch/SVG完成检查。未满足这些条件前，不扩大训练、不调参、不租卡；修订方法后的正式结论仍需新的来源隔离确认数据。
